## 環境需求

- Python 3.10 以上
- Node.js 20+ 及 npm（用於建置前端；若僅執行預先建置好的產物則不需要）
- 可正常連線 Danbooru / Yande.re（必要時需使用代理伺服器）

## 安裝步驟

```bash
# 1. 進入專案目錄
cd D:\crawler

# 2. 建立虛擬環境（選用，建議）
python -m venv venv
venv\Scripts\activate

# 3. 安裝套件
pip install -r requirements.txt
```

## 啟動方式

### 正式模式（單一埠口執行）

前端程式碼位於 `frontend/`，使用 Vue 3 + Vite 撰寫。第一次使用前需要先建置一次靜態產物：

```bash
# 1. 建置前端（第一次 clone 或修改前端程式碼後執行）
cd frontend
npm install
npm run build
cd ..

# 2. 啟動後端，Flask 會託管 frontend 建置好的靜態檔案
python app.py
```

啟動後在瀏覽器開啟：

```
http://127.0.0.1:5173
```

> 若尚未建置前端，`python app.py` 會直接顯示錯誤並提示先執行 `npm run build`。

### 開發模式（前後端熱更新）

修改前端時建議前後端分別啟動，Vite 會把 `/api` 代理到 Flask：

```bash
# 終端機 A：啟動 Flask（預設埠口 5173）
python app.py

# 終端機 B：啟動 Vite 開發伺服器（5174，支援熱更新）
cd frontend
npm run dev
```

在瀏覽器開啟 Vite 顯示的網址（預設 `http://127.0.0.1:5174`）。修改 Vue 檔案後會自動重新整理。

## Danbooru 使用說明

### 1. 設定 API 驗證

Danbooru 匿名存取受限（僅能搜尋安全級別內容，每頁限 20 筆）。建議設定 API Key：

1. 註冊並登入 [danbooru.donmai.us](https://danbooru.donmai.us)
2. 進入個人主頁 → **API Key** 頁面，建立 Key
   - **Permissions**：選 `All` 最省事；若想套用最小權限，請選 `Scoped` 並只勾選 `posts:index` 即可，本專案僅會呼叫 `/posts.json` 一個端點
   - 下載「已刪除圖片」依賴的是**帳號等級**（通常需要 Gold+ 會員），與 API Key 權限無關
3. 將專案根目錄的 `.env.example` 複製為 `.env`，填入憑證：

```bash
DANBOORU_LOGIN=你的使用者名稱
DANBOORU_API_KEY=你的 API Key
```

> `.env` 已列入 `.gitignore`，不會被上傳到 GitHub。程式啟動時會自動載入。

### 2. 搜尋語法

Danbooru 以標籤組合搜尋，多個標籤以空白分隔：

| 範例 | 說明 |
|------|------|
| `hatsune_miku` | 搜尋初音未來相關圖片 |
| `shingeki_no_kyojin` | 搜尋進擊的巨人相關圖片 |
| `hatsune_miku solo` | 多標籤組合 |

> 標籤名稱可於 Danbooru 搜尋框中確認，單字之間以底線連接。

### 3. 含已刪除圖片

開啟後會額外搜尋 `status:deleted` 的貼文並一併下載。已刪除貼文可能無法取得原圖連結，會自動略過。

### 4. 檔案儲存結構

```
downloads/
└── {搜尋關鍵字}/
    └── danbooru/
        └── {作者名}/
            ├── shingeki_no_kyojin(artist_a)_eren_yeager01.jpg
            └── shingeki_no_kyojin(artist_b)_unknown02.png
```

## Yande.re 使用說明

### 1. 搜尋語法

Yande.re 同樣使用標籤搜尋：

| 範例 | 說明 |
|------|------|
| `hatsune_miku` | 搜尋初音未來 |
| `hatsune_miku rating:s` | 僅搜尋安全級別 |

### 2. 標籤類型查詢

首次下載某個搜尋關鍵字時，程式會批次查詢所有標籤的類型（作者 / 角色 / 版權等），用於自動分類檔名與目錄。此步驟會略慢，屬於正常現象。

### 3. 檔案儲存結構

```
downloads/
└── {搜尋關鍵字}/
    └── yande/
        └── {作者名}/
            ├── hatsune_miku(artist_a)_hatsune_miku01.jpg
            └── hatsune_miku(unknown)02.jpg
```

## 評級與標籤篩選

### 評級篩選

每個站點支援四個評級的核取方塊：

| 評級 | 說明 |
|------|------|
| General | 全年齡內容 |
| Sensitive | 輕度敏感內容 |
| Questionable | 偏暴露但未露骨 |
| Explicit | 成人/限制內容 |

只勾選想要下載的評級，未勾選的評級在伺服器端過濾。全部勾選或全部不勾選表示不過濾。

### 標籤規則 — 黑白名單

在搜尋詞之外，支援額外的標籤篩選：

- **黑名單**：包含*任意*黑名單標籤的貼文被排除。黑名單標籤在 API 查詢中使用 `-` 前綴，在伺服器端過濾，節省頻寬。
- **白名單**：僅保留符合白名單標籤的貼文。兩種模式：
  - **AND** — 貼文必須包含*全部*白名單標籤
  - **OR** — 貼文包含*至少一個*白名單標籤即可
- **包含無作者貼文**：白名單啟用時，也下載符合主搜尋詞但沒有作者標籤的貼文。

白名單標籤以結構化資料傳送到後端，不會嵌入搜尋框。搜尋框始終顯示你輸入的原始查詢。

### 檔案類型與大小篩選

- 可獨立切換**靜態圖** (jpg/png/webp)、**動圖** (gif)、**影片** (mp4/webm/swf)。取消勾選的類型在下載時跳過。
- **最大檔案大小**：設定 MB 上限，超過則跳過。留空表示不限制。

### 限制下載數量

設定最多獲取 N 篇貼文。關閉則下載全部符合結果。

## 下載去重

三種模式控制是否跳過已下載的貼文：

| 模式 | 行為 |
|------|------|
| **不跳過** | 一律下載，不檢查歷史紀錄 |
| **僅當前搜尋詞**（預設） | 跳過*同一搜尋詞*下已下載過的貼文 |
| **全域** | 跳過本站點*任何搜尋詞*下已下載過的貼文 |

歷史紀錄始終按搜尋詞儲存，不受去重模式影響。預設的「僅當前搜尋詞」保持原有行為。

## 自動重試

開啟後，主下載流程完成後自動重試一次所有失敗項目（每個檔案最多嘗試 3 次）。無需手動點擊重試按鈕，進度即時顯示在日誌中。

## 下載紀錄管理

程式會在 `downloads/` 目錄下儲存兩個紀錄檔：

| 檔案 | 說明 |
|------|------|
| `.downloaded_danbooru.json` | Danbooru 已下載貼文 ID |
| `.downloaded_yande.json` | Yande.re 已下載貼文 ID |

兩個站點的紀錄完全獨立，重設一個不會影響另一個。

### 管理紀錄

- **重設**：點擊每筆紀錄右側的**重設**按鈕可清除該搜尋詞的下載紀錄。下次執行時會重新下載所有圖片。
- **重新整理**：從磁碟重新讀取紀錄（外部修改紀錄檔後適用）。
- 批次備份與合併請見下方[匯入匯出紀錄](#匯入匯出紀錄)。

紀錄檔採用原子寫入（暫存檔 + `os.replace`），防止意外關閉導致資料遺失。

## 匯入匯出紀錄

下載紀錄面板提供**匯出**和**匯入**按鈕：

- **匯出**：下載一份包含所有下載紀錄的 JSON 備份（兩個站點、全部搜尋詞），可用於備份或遷移。
- **匯入**：選取之前匯出的 JSON 檔案合併紀錄，重複 ID 自動跳過。

格式：
```json
{
  "version": 1,
  "exported_at": "2026-06-08T12:00:00",
  "danbooru": { "搜尋詞": [123, 456] },
  "yande": { "搜尋詞": [789, 101] }
}
```

點擊右上角**齒輪圖示**開啟設定面板。修改儲存在 `localStorage` 中，跨工作階段保留。

## 常見問題

**Q: 執行時遇到 403 錯誤？**
A: Danbooru 匿名存取受限，請於專案根目錄建立 `.env` 並填寫 API 驗證資訊（參考 `.env.example`）。

**Q: 圖片下載速度慢？**
A: 程式每張圖片之間有 0.5~1 秒間隔，用以避免觸發站點的請求頻率限制，屬於正常現象。

**Q: 部分圖片沒有下載連結？**
A: 已刪除貼文的原圖可能已從伺服器移除，程式會自動略過並於日誌中提示。

**Q: 切換分頁後任務還在執行嗎？**
A: 是的。切換分頁只是切換介面顯示，背景任務不受影響。右側日誌面板可隨時切換檢視兩個站點各自的即時日誌。

**Q: 如何暫停任務？**
A: 點擊開始按鈕旁的 **⏸** 按鈕，任務會在當前圖片下載完成後暫停（不會於中途截斷檔案）。點擊 **▶** 繼續。

**Q: 如何中止任務？**
A: 點擊 **⏹** 中止按鈕，於確認視窗確認後，任務會在當前圖片下載完成後離開（同樣不會截斷檔案）。已下載的圖片與紀錄會全部保留，下次執行時會自動跳過。中止 Danbooru 任務不會影響正在執行的 Yande 任務，兩者完全獨立。

**Q: 要更換搜尋關鍵字怎麼辦？**
A: 先點 **⏹** 中止當前任務，待狀態變為「已中止」後修改搜尋關鍵字，再點開始即可。不需重新整理頁面，另一個站點的任務也不會受影響。

**Q: 意外關閉頁面後，任務還在嗎？**
A: 關閉瀏覽器只會切斷前端連線，背景 Flask 服務與下載執行緒仍在執行。重新開啟頁面後可看到最新狀態。但關閉 `app.py` 行程（Ctrl+C）會終止所有任務。

**Q: 兩個站點可以同時執行嗎？**
A: 可以。Danbooru 與 Yande.re 屬於兩個獨立網域，同時執行一個 Danbooru 任務與一個 Yande.re 任務完全沒問題，不會互相影響。但不建議在同一站點同時執行多個任務（請求頻率會疊加，容易觸發限流）。

**Q: 如何按評級篩選？**
A: 在篩選區的評級核取方塊中選取。只有勾選的評級才會下載。全部不選或全部勾選表示不過濾。

**Q: 黑白名單如何使用？**
A: 黑名單排除包含*任意*符合標籤的貼文。白名單僅保留符合的貼文，可切換 AND/OR 模式控制匹配方式。兩者皆在伺服器端過濾以節省頻寬。

**Q: 下載去重是什麼？**
A: 去重模式控制已下載過的貼文是否跳過。「僅當前搜尋詞」（預設）跳過同搜尋詞下已下載的貼文。「全域」跳過該站點所有搜尋詞下已下載的貼文。「不跳過」一律重新下載。

**Q: 如何備份下載紀錄？**
A: 在下載紀錄面板點擊**匯出**按鈕，下載 JSON 備份檔。使用**匯入**按鈕在其他裝置還原或合併紀錄。

**Q: 可以自訂檔案命名與目錄結構嗎？**
A: 可以。開啟設定 → 下載分頁，設定路徑與檔名範本，支援 `{artist}`、`{query}`、`{id}`、`{md5}`、`{date}`、`{rating}` 等佔位符。

**Q: 鍵盤快速鍵有哪些？**
A: `Ctrl+Enter` 開始下載，`Ctrl+.` 中止任務，`?` 開啟教學，`,` 開啟設定。
