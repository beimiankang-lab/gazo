## 环境要求

- Python 3.10 及以上
- Node.js 20+ 及 npm（用于构建前端；仅后端跑预构建产物时不需要）
- 网络可正常访问 Danbooru / Yande.re（必要时需挂代理）

## 安装步骤

```bash
# 1. 进入项目目录
cd D:\crawler

# 2. 创建虚拟环境（可选，推荐）
python -m venv venv
venv\Scripts\activate

# 3. 安装依赖
pip install -r requirements.txt
```

## 启动方式

### 生产模式（一个端口跑完）

前端代码在 `frontend/` 下用 Vue 3 + Vite 编写，第一次使用需要先构建一次静态产物：

```bash
# 1. 构建前端（首次 clone 或改过前端代码时执行）
cd frontend
npm install
npm run build
cd ..

# 2. 启动后端，Flask 会托管 frontend 构建好的静态文件
python app.py
```

启动后在浏览器打开：

```
http://127.0.0.1:5173
```

> 如果还没构建过前端,`python app.py` 会直接报错提示去跑 `npm run build`。

### 开发模式（前后端热更新）

修改前端时推荐分端开发，Vite 会把 `/api` 代理到 Flask：

```bash
# 终端 A：启动 Flask（默认 5173）
python app.py

# 终端 B：启动 Vite 开发服务器（5174，带热更新）
cd frontend
npm run dev
```

浏览器打开 Vite 给出的地址（默认 `http://127.0.0.1:5174`），改 Vue 文件会自动刷新。

## Danbooru 使用说明

### 1. 配置 API 认证

Danbooru 匿名访问受限（只能搜索安全级别内容，每页限 20 条）。建议配置 API Key：

1. 注册并登录 [danbooru.donmai.us](https://danbooru.donmai.us)
2. 进入个人主页 → **API Key** 页面，生成 Key
   - **Permissions**：选 `All` 最省心；如果想按最小权限配置，选 `Scoped` 并只勾 `posts:index` 即可，本项目只调用 `/posts.json` 一个接口
   - 下载「已删除图片」依赖**账号等级**（通常需要 Gold+ 会员），与 API Key 权限无关
3. 启动程序后，打开 **设置 → API 密钥**，填入用户名和 API Key 并点击保存。凭据会保存到可执行文件同目录下的 `gazo_config.json`。

### 2. 搜索词格式

Danbooru 使用标签组合搜索，多个标签用空格分隔：

| 示例搜索词 | 说明 |
|-----------|------|
| `hatsune_miku` | 搜索初音未来相关图片 |
| `shingeki_no_kyojin` | 搜索进击的巨人相关图片 |
| `hatsune_miku solo` | 多标签组合 |

> 标签名称可在 Danbooru 网站搜索框中确认，单词间用下划线连接。

### 3. 含已删除图片

开启后会额外搜索 `status:deleted` 的帖子并一并下载。已删除帖子可能无法获取原图链接，会自动跳过。

### 4. 文件保存结构

```
downloads/
└── {搜索词}/
    └── danbooru/
        └── {作者名}/
            ├── shingeki_no_kyojin(artist_a)_eren_yeager01.jpg
            └── shingeki_no_kyojin(artist_b)_unknown02.png
```

## Yande.re 使用说明

### 1. 搜索词格式

Yande.re 同样使用标签搜索：

| 示例搜索词 | 说明 |
|-----------|------|
| `hatsune_miku` | 搜索初音未来 |
| `hatsune_miku rating:s` | 只搜索安全级别 |

### 2. 标签类型查询

首次下载某个搜索词时，程序会批量查询所有标签的类型（作者 / 角色 / 版权等），用于自动归类文件名和目录，此步骤会稍慢，属正常现象。

### 3. 文件保存结构

```
downloads/
└── {搜索词}/
    └── yande/
        └── {作者名}/
            ├── hatsune_miku(artist_a)_hatsune_miku01.jpg
            └── hatsune_miku(unknown)02.jpg
```

## 评级与标签过滤

### 评级过滤

每个站点支持四个评级的复选框：

| 评级 | 说明 |
|------|------|
| General | 全年龄内容 |
| Sensitive | 轻度敏感内容 |
| Questionable | 偏暴露但未露骨 |
| Explicit | 成人/露骨内容 |

只勾选想要下载的评级，未勾选的评级在服务端过滤。全部勾选或全部不勾选表示不过滤。

### 标签规则 — 黑白名单

在搜索词之外，支持额外的标签过滤：

- **黑名单**：包含*任意*黑名单标签的帖子被排除。黑名单标签在 API 查询中使用 `-` 前缀，在服务端过滤，节省带宽。
- **白名单**：仅保留匹配白名单标签的帖子。两种模式：
  - **AND** — 帖子必须包含*全部*白名单标签
  - **OR** — 帖子包含*至少一个*白名单标签即可
- **只下载无作者帖子**：开启后**只**下载没有作者标签的帖子（跳过常规搜索结果）。可与白名单/黑名单组合使用。

白名单标签以结构化数据发送到后端，不会嵌入搜索框。搜索框始终显示你输入的原始查询。

### 文件类型与大小过滤

- 可独立切换**静态图** (jpg/png/webp)、**动图** (gif)、**视频** (mp4/webm/swf)。取消勾选的类型在下载时跳过。
- **最大文件大小**：设置 MB 上限，超过则跳过。留空表示不限制。

### 限制下载数量

设置最多获取 N 个帖子。关闭则下载全部匹配结果。

## 下载去重

三种模式控制是否跳过已下载的帖子：

| 模式 | 行为 |
|------|------|
| **不跳过** | 始终下载，不检查历史记录 |
| **仅当前搜索词**（默认） | 跳过*同一搜索词*下已下载过的帖子 |
| **全局** | 跳过本站点*任何搜索词*下已下载过的帖子 |

历史记录始终按搜索词保存，不受去重模式影响。默认的「仅当前搜索词」保持原有行为。

---
## 自动重试

开启后，主下载流程完成后自动重试一次所有失败项（每个文件最多尝试 3 次）。无需手动点击重试按钮，进度实时显示在日志中。

## 下载记录管理

程序会在 `downloads/` 目录下保存两个记录文件：

| 文件 | 说明 |
|------|------|
| `.downloaded_danbooru.json` | Danbooru 已下载帖子 ID |
| `.downloaded_yande.json` | Yande.re 已下载帖子 ID |

两个站点的记录完全独立，重置一个不影响另一个。

### 管理记录

- **重置**：点击每条记录右侧的**重置**按钮可清除该搜索词的下载记录。下次运行时会重新下载所有图片。
- **刷新**：从磁盘重新读取记录（外部修改记录文件后可用）。
- 批量备份和合并请参见下方[导入导出记录](#导入导出记录)。

记录文件采用原子写入（临时文件 + `os.replace`），防止意外关闭导致数据丢失。

## 导入导出记录

下载记录面板提供**导出**和**导入**按钮：

- **导出**：下载一份包含所有下载记录的 JSON 备份（两个站点、全部搜索词），可用于备份或迁移。
- **导入**：选择之前导出的 JSON 文件合并记录，重复 ID 自动跳过。

格式：
```json
{
  "version": 1,
  "exported_at": "2026-06-08T12:00:00",
  "danbooru": { "搜索词": [123, 456] },
  "yande": { "搜索词": [789, 101] }
}
```

## 设置

点击右上角**齿轮图标**打开设置面板。修改保存在 `localStorage` 中，跨会话保留。

| 选项卡 | 选项 |
|--------|------|
| **通用** | 界面语言 (EN / 简体中文 / 繁體中文 / 日本語)、主题色 (紫/天蓝/粉/薄荷绿/琥珀橙/珊瑚红) |
| **下载** | 各站点并发数 (1–8)、默认保存目录、文件名模板（支持占位符如 `{id}`、`{artist}`、`{query}`、`{ext}`、`{md5}`、`{date}`、`{rating}` 等）|
| **过滤** | 默认评级、文件类型、最大文件大小预设 |
| **API 密钥** | Danbooru 用户名 + API Key，支持连接测试 |

## 常见问题

**Q: 运行时遇到 403 错误？**
A: Danbooru 匿名访问受限，请在程序中打开 **设置 → API 密钥**，填入 Danbooru 用户名和 API Key 并保存。

**Q: 图片下载很慢？**
A: 程序每张图片之间有 0.5~1 秒间隔，这是为了避免触发站点的请求频率限制，属正常现象。

**Q: 部分图片没有下载链接？**
A: 已删除帖子的原图可能已从服务器移除，程序会自动跳过并在日志中提示。

**Q: 切换选项卡后任务还在跑吗？**
A: 是的。切换选项卡只是切换界面显示，后台任务不受影响。右侧日志面板可随时切换查看两个站点各自的实时日志。

**Q: 如何暂停任务？**
A: 点击开始按钮旁边的 **⏸** 按钮，任务会在当前图片下载完成后暂停（不会中途截断文件）。点击 **▶** 继续。

**Q: 如何中止任务？**
A: 点击 **⏹** 中止按钮，弹出确认框，确认后任务会在当前图片下载完成后退出（同样不会截断文件）。已下载的图片和记录全部保留，下次运行会自动跳过。中止 Danbooru 任务不会影响正在跑的 Yande 任务，两者完全独立。

**Q: 想换搜索词怎么办？**
A: 先点 **⏹** 中止当前任务，等状态变成「已中止」后修改搜索词，再点开始即可。不需要刷新页面，这样另一个站点的任务不会受影响。

**Q: 意外关闭页面，任务还在吗？**
A: 关闭浏览器只断开了前端连接，后台 Flask 服务和下载线程仍在运行。重新打开页面后可以看到最新状态。但关闭 `app.py` 进程（Ctrl+C）会终止所有任务。

**Q: 两个站点可以同时跑吗？**
A: 可以。Danbooru 和 Yande.re 是两个独立域名，同时跑一个 Danbooru 和一个 Yande.re 任务完全没问题，不会互相影响。但不建议同一站点同时跑多个任务（总请求频率叠加，容易触发限流）。

**Q: 如何按评级过滤？**
A: 在过滤区域的评级复选框中选择。只有勾选的评级才会下载。全部不选或全部勾选表示不过滤。

**Q: 黑白名单怎么用？**
A: 黑名单排除包含*任意*匹配标签的帖子。白名单只保留匹配的帖子，通过 AND/OR 切换控制匹配方式。两者均在服务端过滤以节省带宽。

**Q: 下载去重是什么意思？**
A: 去重模式控制已下载过的帖子是否跳过。「仅当前搜索词」（默认）跳过同搜索词下已下载的帖子。「全局」跳过该站点所有搜索词下已下载的帖子。「不跳过」始终重新下载。

**Q: 如何备份下载记录？**
A: 在下载记录面板点击**导出**按钮，下载 JSON 备份文件。使用**导入**按钮在其他机器恢复或合并记录。

**Q: 可以自定义文件命名和目录结构吗？**
A: 可以。打开设置 → 下载选项卡，配置路径和文件名模板，支持 `{artist}`、`{query}`、`{id}`、`{md5}`、`{date}`、`{rating}` 等占位符。

**Q: 键盘快捷键有哪些？**
A: `Ctrl+Enter` 开始下载，`Ctrl+.` 中止任务，`?` 打开教程，`,` 打开设置。
